# iOS Shadowrocket 当前节点统一出口配置

## 文件

- 配置文件：`taiwan-no-leak.conf`
- 严格配置：`strict-proxy-no-ipv6.conf`
- 国内直连配置：`cn-direct-no-ipv6.conf`
- 用途：除局域网和联网认证外，所有公网流量交给 iOS Shadowrocket 当前选中的代理节点。
- IPv6：通过首条 `IP-CIDR6,::/0,REJECT,no-resolve` 规则硬阻断公网 IPv6；这比单独设置 `ipv6 = false` 更严格。
- 文件不包含节点、订阅地址、密码或证书。请在 iPhone 上继续使用自己的订阅，并按需要选择美国、台湾或其他节点。

如果规则模式下仍出现本机中国 IPv4，请改用 `strict-proxy-no-ipv6.conf`。严格配置没有任何 `DIRECT` 规则：全部 IPv6 拒绝，全部 IPv4 交给当前选中的代理节点。代价是局域网设备、路由器后台和部分 Wi-Fi 认证页面可能暂时无法访问。

如果严格配置导致微信、国内应用或国内网站不稳定，请使用 `cn-direct-no-ipv6.conf`：IPv6 全部拒绝，微信/腾讯和中国大陆 IPv4 直连，其他公网 IPv4 使用当前选中的节点。国内直连意味着国内服务会看到设备的正常中国公网 IPv4，这是分流设计，不是异常泄露。

## 一、把配置传到 iPhone

任选一种方式：

1. 在 Mac 的 Finder 中找到 `taiwan-no-leak.conf`。
2. 通过 AirDrop 发送到 iPhone，选择用 Shadowrocket 打开；或者先保存到 iCloud Drive 的“下载”目录。
3. 不要通过公开网盘或聊天群发送带有节点凭据的完整订阅。本文件不含凭据，可以单独传输。

## 二、在 iOS Shadowrocket 导入

配置路径：

`Shadowrocket → 配置 → 右上角“+” → 从文件导入`

如果文件已在 iOS“文件”App 中，也可以：

`文件 → taiwan-no-leak.conf → 分享 → Shadowrocket`

导入后：

1. 返回 `Shadowrocket → 配置`。
2. 点击 `taiwan-no-leak.conf`，使其出现选中标记。
3. 返回首页。
4. 从现有订阅中选择本次需要使用的稳定节点。
5. 点击“全局路由”，选择“配置”。不要选择“直连”。

如果此前已导入过旧版本，请先删除旧的同名配置或使用新名称重新导入，并再次确认选中标记位于新配置上。修改 Mac 上的文件不会自动同步到 iPhone。

## 三、设置隧道防绕行

路径：

`Shadowrocket → 设置 → 隧道`

建议设置：

- 强制路由：开启
- 包括所有网络：开启
- 包括本地网络：关闭
- 包括 APNs：关闭；如通知异常可再测试开启
- 包括蜂窝服务：保持默认

说明：“包括所有网络”用于减少应用绕过隧道，但手动关闭 Shadowrocket 后，iOS 仍可能恢复普通网络，它不是受监管设备级的绝对 Kill Switch。

## 四、设置 UDP 与 WebRTC

路径：

`Shadowrocket → 设置 → UDP`

建议设置：

- 开启转发：开启
- 禁用 STUN：开启
- 允许端口：留空
- 超时：30 秒

“禁用 STUN”可降低 WebRTC 暴露真实公网 IP 的风险，但可能影响网页语音、视频会议和 P2P 通信。

## 五、按需连接

路径：

`Shadowrocket → 设置 → 按需求连接`

如希望切换 Wi-Fi、蜂窝网络或唤醒后自动恢复隧道，可启用“始终开启/Always On”或对应的按需规则。不同 iOS/Shadowrocket 版本的文字可能略有差异。

按需连接负责自动重连，不等同于代理节点故障时绝对阻止所有物理网络流量。

## 六、启用并验证

1. 首页确认选择的是本次需要使用的节点。
2. 打开 Shadowrocket 连接开关。
3. 先访问 Cloudflare Trace 或可信 IP 检测网站，确认网页出口为台湾。
4. 再做 DNS 泄露检测；DNS 解析器可能显示台湾、新加坡或美国，这不等于网页公网出口泄露。
5. 做 WebRTC 检测，确认页面没有显示运营商的真实公网地址。
6. 分别用 Wi-Fi 和蜂窝网络测试一次。

如果检测页仍出现中国公网 IPv4：

1. 临时把首页“全局路由”切换为“代理”并重新连接；若中国 IPv4 消失，说明此前仍有配置规则或旧配置在直连。
2. 若 Cloudflare、Claude 等出口地区与所选节点的预期地区不一致，说明节点的真实出口或 IPv6 出口位于其他地区；节点名称不能作为出口证明，需要更换实际检测结果符合预期的节点。
3. 检查 `设置 → Apple 账户 → iCloud → 专用代理` 以及当前 Wi-Fi/蜂窝网络的“限制 IP 地址跟踪”，避免 Apple 专用代理形成额外出口。

## 七、已移除的 Mac 规则

Mac 当前 `default.conf` 中存在大量公网直连规则，例如：

- `GEOIP,CN,DIRECT`
- 百度、淘宝、腾讯、网易等域名 `DIRECT`
- Apple 公网段和部分下载、测速域名 `DIRECT`

本 iOS 配置不包含这些规则。只有回环地址、私有局域网、链路本地地址和 `captive.apple.com` 保持直连；其他公网目标统一由 `FINAL,PROXY` 处理。

## 八、恢复方法

如果导入后出现问题：

1. `Shadowrocket → 配置`，重新选择原来的配置文件。
2. 或将首页“全局路由”临时切换回原设置。
3. 不需要删除节点或订阅。

若只是局域网设备无法访问，先检查“包括本地网络”是否关闭，并确认目标确实属于私有地址段；不要直接加入宽泛的公网 `DIRECT` 规则。
